# 在 macOS 上分开查找和清理卸载残留

[English](2026-11-28-macos-uninstall-leftovers.md)

状态: accepted

## 问题

卸载程序后，下载文件、设置、用户数据和其他程序中的引用可能仍然存在。名称匹配也可能找到无关文件。共享配置中的引用不代表整个配置文件是清理目标。工具应帮助用户核对结果，不能把搜索当成清理授权。

## 决策

项目维护者已选定以下首版约束：

- 命令名为 `lfd`，取自 leftover data（残留数据）。首版仅支持 macOS。覆盖 Homebrew formula 和 cask、直接下载的独立可执行文件、拖拽安装的 `.app`，以及 `.pkg` 安装。安装来源未知时仍查找相关文件和引用。不承诺还原任意安装脚本执行过的操作。
- 只检查文档列出的固定位置。除主程序检查位置外，查找范围包括 `~/Library` 下常见的用户应用数据、偏好和缓存目录，以及 `~/.config`、`~/.local/share`、`~/.local/state`、`~/.cache` 和当前用户的专用临时目录。只在指定来源中读取文件内容并查找引用，例如选定的 OpenCode 配置文件和 Pi 扩展目录。不搜索整个主目录、浏览器数据或 Shell 历史。分别报告无法检查的位置和未找到匹配项的位置。
- 找到主程序时，将匹配结果标为[关联项](../../GLOSSARY.md#uninstall-leftover-inspection)。只有必要检查已完成且未发现主程序时，才将结果标为残留候选，并说明检查范围的限制。必要检查未完成时仅显示可能匹配。展示匹配证据，并在可以判断时标明用途类别。
- 查找保持只读。用户可以在独立的清理流程中处理自己选中的项目。界面采用证据分栏：左侧浏览和勾选，右侧展示当前项的完整路径、匹配证据和已知风险。

项目维护者还选定以下查找和清理规则：

- 接受应用名称或精确标识符，例如 Bundle ID、Homebrew 包名或 `.pkg` 包标识符。不接受任意路径作为搜索输入。用户输入的标识符可以缩小查找范围，但本身不是归属证据。
- 使用本机证据，例如 `.app` 元数据、Homebrew 本地记录和已登记的 `.pkg` 收据。不解析下载的安装包，也不执行安装或卸载脚本。记录缺失时继续查找。证据不足的结果仅供查看。
- 证据能区分多个同名应用时，请用户先选一个。显示可用的应用标识符和安装位置。不合并结果，也不把仅名称匹配当成归属证据。
- 使用 `.pkg` 安装收据提供证据和范围内的待检查路径。检查路径是否仍存在。收据本身不能证明路径目前归应用所有，也不使路径符合清理条件。不清理收据。
- 对 `.app` 检查常见应用目录，对独立命令检查 `PATH`。有 Homebrew 安装线索时，再检查相关的 Homebrew 位置。无法确定程序形态时，同时检查应用目录和 `PATH`。
- 找到主程序或无法完成必要的主程序检查时，结果仅供查看。无法读取与主程序检查无关的位置，例如缓存目录，本身不阻止清理其他已核实的路径。
- 仅允许勾选清理范围内且有证据表明归应用专用的路径。实际清理范围仅限标准应用容器目录 `~/Library/Containers/<bundle-id>`。必须能核实其中的本机 macOS `.com.apple.containermanagerd.metadata.plist`，且其字段 `MCMMetadataIdentifier` 与目录的 Bundle ID 精确一致。元数据缺失、不可读、不一致或是链接均不能授予清理许可。此证据只适用于该容器，不适用于同名缓存、偏好、其他应用数据或共享容器。查询标识符、路径名称或收据本身均不授予清理许可。只展示共享引用，不删除或改写它们。
- 以本机实际 macOS 账户核定容器清理许可及私有废纸篓位置。环境变量不得扩大清理范围。勾选前，组合检查应用包、独立命令、Homebrew 和收据提供的主程序线索；不得因精确标识符匹配或身份选择而忽略已经找到的主程序及未完成的必要检查。其他位置中的匹配项仅供查看。
- 已核实归应用专用的目录可以整体勾选。确认界面说明移动包含子项。如果同时选中目录和其中的子项，只确认和移动该目录。不沿符号链接进入目标，也不允许单独清理符号链接。移动合格目录不应改动其中符号链接的目标。
- 初始不勾选任何项。按回车查看已勾选项。确认界面列出完整路径，标明对保留的用户数据有哪些已知影响，并默认选中「取消」。用户必须明确选择「移到废纸篓」并确认。用户数据不另设一轮确认。
- 移动每个已确认的路径前，再次检查主程序状态和账户，并复核容器、元数据及祖先目录的身份、类型、归属和范围，不跟随符号链接。对象被替换、变成符号链接或无法核实时，跳过并报告原因。不把原确认用于新对象。
- 将用户确认的路径移到该账户同卷的私有废纸篓，不覆盖已有项目。无法核实或移动失败时保留原项并报告原因。不请求提权，也不改用永久删除。

工具的 README 将列出查找目录、引用来源和可清理目录。命令名不决定分发包名。

## 备选方案

- 仅提供只读报告：工具不会改动任何数据，但用户需在工具外逐项处理。项目维护者选择加入选择性清理。
- 清理所有搜索命中项：操作更少，但名称匹配可能指向无关文件或共享引用。查找和清理分开的决定排除了此方案。
- 原型比较了表格加底部详情、证据分栏和以清理队列为主的布局。项目维护者选定证据分栏。用户浏览列表时可以同时查看当前项的证据。独立的清理队列不属于已选布局。

## 后果与风险

限定范围的搜索可能漏掉范围外的文件。未发现主程序不等于已经卸载。即使路径归应用所有，移走它也可能影响保留的设置、会话或其他用户数据。匹配证据能说明关联，不能证明可以安全移除。复核路径能降低误处理替换对象的风险，但路径仍可能在复核后、移动前发生变化。

原型保存在本地分支 `prototype/app-leftovers` 的提交 `c098828` 中。原型使用虚构数据，只模拟清理。浏览器和 macOS 伪终端检查只验证了交互，没有验证扫描或真实文件操作。使用隔离的测试文件和目录验证清理。对已有应用和用户数据只做只读查找验证。

本决策不改变已接受的 [CLI 源码布局](2026-11-20-cli-source-layout.zh.md)或[分发设计](2026-11-20-npm-cli-distribution.zh.md)。
