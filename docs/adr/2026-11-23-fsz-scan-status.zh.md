# 显示 `fsz` 扫描状态，不显示百分比

[English](2026-11-23-fsz-scan-status.md)

状态: implemented

## 问题

`fsz` 遍历完目录后才输出大小明细。扫描耗时较长时，用户看不到扫描是否仍在推进。扫描过程中才会发现下级条目，因此 `fsz` 无法提前知道条目总数。

## 决策

项目维护者选择只扫描一遍。扫描状态显示累计访问的条目数，不显示完成百分比，也不估算剩余时间。扫描状态不改变[统计规则](../../crates/fsz/README.zh.md#统计规则)。

项目维护者还确认，仅在标准错误连接到终端时显示临时状态行。扫描返回时清除状态行，包括扫描返回错误时。最终明细仍写到标准输出。

扫描每发现一个目录项就计一次，包括随后跳过或无法读取的目录项。扫描根目录不计入。未返回目录项的枚举错误也不计入。这个计数表示已访问的条目数，不表示成功测量的条目数。

扫描开始至少 250 毫秒后，发现下一个目录项时首次显示状态行。此后，只有发现新的目录项，并且距上次刷新至少 250 毫秒，才刷新状态行。目录扫描和状态显示代码已按此设计实现，没有新增依赖。本议题独立于工作区布局和分发决策。

## 备选方案

- 预先遍历一次以统计条目总数：会在测量前增加一次遍历。如果目录在两次遍历之间发生变化，预先统计的总数也可能失效。
- 用扫描根目录的直接子条目数计算百分比：一个文件与一个含有大量下级条目的目录权重相同，百分比可能无法反映剩余工作量。

## 后果与风险

条目数可以表明扫描正在推进，但不能说明完成比例，也不能预测何时结束。如果某次文件系统操作耗时较长，计数会等到扫描继续后才有机会更新。状态显示代码覆盖终端中的一行。如果终端将状态行折行，清除后可能有文字残留。

macOS arm64 上，使用锁定依赖的离线工作区测试和 `fsz` 符号链接冒烟检查均通过。使用伪终端测试构建后的 CLI，确认长扫描会显示并清除状态行，快速扫描不显示状态行。重定向标准错误不会输出状态行，也不会改变标准输出。尚未在 Linux 和 Windows 上验证此功能的原生终端行为。
